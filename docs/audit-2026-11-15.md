# EntityLens audit, 15 November 2026

Review decisions in this audit used a separate copy of the workspace. The original workspace retained its three previously undone decisions and zero active decisions.

| Finding | Fix |
| --- | --- |
| The API accepted a new decision on a removed candidate. Undo could put a removed candidate back in the queue. | Only pending pairs accept a new decision. A matching run saves the current proposal for each reviewed pair. Undo restores that proposal or marks the pair as removed if the run did not return it. |
| Coordinates could combine a latitude and longitude from different records. | The directory and export take both coordinates from the same complete source observation. Original values remain in the source records. |
| An error in a secondary panel could block the review queue. | The queue fetches only its own results. Each other view reports its own errors. The frontend checks that source evidence matches both the selected proposal revision and the current source versions before enabling a decision. |
| The Vite development server sent API calls to port 8000. | The proxy now targets port 8765, the project's default. The backend resolves its reports and built interface from the project root. |
| Some states were hard to distinguish or see without scrolling. | The interface uses readable decision labels, a filter for removed candidates, and progress or refresh guidance beside the decision buttons. Source checks sit closer to the comparison table. |

Browser checks used public NYC DOHMH and Overture records in an isolated database. Temple Court passed the note, confirmation, directory, CSV, JSON, permalink and undo flow. Parcelle pairs with conflicting street numbers disabled linking and allowed a Different places decision. The Unsure outcome appeared in its filter. Search trimmed surrounding spaces and cleared the decision controls for empty results. A changed Donut Pub source preserved the reviewed entity, disabled export and appeared as a fresh proposal after matching and undo. Matching completed after queueing, and a second run completed after cancellation and retry. Temporary decisions did not enter the working database.

Verification included 50 Python tests, the TypeScript and production builds, the Vite proxy, and browser layouts at 1280 and 676 CSS pixels. A Linux ARM64 Docker build and an isolated Compose run loaded 7,118 records and 66,660 candidate pairs. The API and worker completed a matching run against their shared SQLite volume.

Both raw snapshot hashes matched their manifests. Training on copied inputs reproduced the split hash, selected model, validation metrics and test metrics. The labels are heuristic, so the experiment does not measure accuracy against independent human judgments. Candidate recall and cluster quality still need independent evaluation. The test suite emits a Starlette TestClient deprecation warning.
