# Concord workbench redesign

## Reference selection

Reviewed public product screens on 2026-10-27. The reference set uses shipped applications and their documented workflows, rather than speculative dashboard concepts. This does not assert how every part of those products was authored.

| Reference | Material actually inspected | Decision for Concord |
| --- | --- | --- |
| [Linear Triage](https://linear.app/docs/triage) | Official documentation and embedded Triage screen | An inbox with a persistent candidate list and one selected item; quieter navigation; compact controls |
| [Attio record merging](https://attio.com/help/reference/managing-your-data/records/merge-and-delete-records) | Official merge documentation and enlarged Amazon record comparison screenshot | Explicitly distinguish both sources and expose a deliberate confirmation action. Concord adapts this to a field-aligned table, rather than copying Attio's record cards or merge semantics |
| [Front in Nicelydone](https://nicelydone.club/examples/apps/front) | Public gallery, including the shared-inbox empty screen | Separate navigation, queue and detail regions; restrained hierarchy; handle an empty inbox as a real state |
| [Mobbin web collection](https://mobbin.com/discover/apps/web) | Landing content accessible; initial interactive navigation timed out | Discovery only. No inaccessible screenshots were used as evidence |

No third-party screenshots, logos, templates or interface assets are embedded in the product. Existing Lucide icons remain in use. The palette and layout implementation are specific to Concord.

## Product decisions

- The review screen opens directly into an inbox layout. Repeated summary counters and the extra section heading no longer precede the main task.
- Warm gray navigation, a restrained terracotta selection marker, olive controls and fine separators replace the blue card treatment. System fonts keep the application independent of font services.
- Source fields share table rows, so different-length place names cannot misalign addresses and phone numbers. Missing values remain explicit. Source identifiers and versions are available in a disclosure.
- `Values differ` is a display comparison: NFKC, whitespace and case normalization only. Highlighting does not determine identity or change model features, labels, constraints or scores. Coordinate values may differ even when nearby.
- The queue and selected item scroll independently on desktop. Decision buttons remain in a dedicated footer. Selecting another pair returns its detail pane to the top; keyboard navigation keeps the selected queue row visible.
- On a narrow screen the queue and selected pair are separate views, with a visible return action. History permalinks open the detail view directly. Returning to the queue restores its search and filters.
- Location schematic and checklist move into a disclosure available at every width, instead of taking a permanent third column or disappearing at intermediate widths.
- A missing evidence note focuses its field and displays an associated validation message. It does not resemble a failed service request.
- Sources, Entities and Evaluation share the same type, controls, spacing and palette. Review-only policy and silver-label limitations remain explicit.

## Verification

Automated checks: 46 Python regression tests, TypeScript checking and a production frontend build. Existing Starlette TestClient dependency deprecation warning remains.

Browser verification and actual viewport dimensions are recorded with the screenshots in `docs/screenshots`. Checks cover queue selection, model/rule disagreement and merge blockers, missing-note validation, search and empty states, source versions, optional details, other application pages, and narrow queue/detail navigation. Test decisions are not needed to establish a layout change; existing reviewed data is preserved.

This redesign makes no new claim about independent ML accuracy, deployment, scale or human gold labels. SQLite and the existing review-only policy remain in use.

Verified browser views:

- Desktop: **1280 × 720**, [default review](screenshots/redesign-desktop-2026-10-27.png) and [blocked merge](screenshots/redesign-conflict-2026-10-27.png). No document overflow in either direction; queue and detail have their own scrolling regions.
- Narrow: **536 × 988**, [full detail capture](screenshots/redesign-narrow-2026-10-27.png). No horizontal document overflow. Queue → detail → queue, history link → reload → Return to queue verified.
- Missing-note validation focuses the field and announces the associated error; changing the candidate clears an unsaved note. J/K, identifier and feature disclosures, location checklist, Sources & Runs, Entities and Evaluation inspected. No browser console errors or warnings in the final desktop session.

These are local browser checks at the actual dimensions above, not a claim of complete device or cross-browser accessibility coverage. No review decision was added during this redesign verification.
